一些思考来自于 2025 年做 WebFactory 的时候，很遗憾当时为了 ICLR 中稿在论文写作上做了很大的妥协，导致没有大篇幅地写环境合成和任务合成，只强调了环境可观察这件事对于合成环境、合成任务和合成对应的验证器的助力和重要性。今天算是把缺的这一块补上了。

论文 WebFactory：arXiv:2603.05044。

## Long-horizon agentic 任务怎么合成，造数据怎么造

随着模型的能力提升，现在大的趋势是，造任务的能力跟不上模型做任务的能力，大家苦于造不出更难更复杂的任务。

比如在 Ubuntu、macOS 和 Windows 系统中，如何造出更难更复杂的 cowork 任务、computer-use 任务，包括跨网站的信息搜集与整合、多约束条件下的决策、涉及多个工具或应用协同完成的 workflow，以及那些必须根据中间结果动态调整后续步骤的开放式任务。

简而言之，**如何持续生成超出当前模型能力边界、同时又可执行、可验证、可自动判分的高难度任务？**

## 前沿 LLM 合成任务的三个问题

让前沿 LLM 辅助合成任务，现在主要的问题是：

1. 模型合成的任务难度不够高，不满足 SFT 数据和 RL 任务收集的要求。
2. 模型有幻觉，合成的任务不一定能在环境中执行。可能合成的是错误的、不可执行的任务。
3. 合成任务的多样性不够。比如让 Opus 5 合成 20 个 Windows 上涉及 Word、Excel 的任务，效果还可以，多样性也还行。如果变成合成 100 个，可能多样性就断崖下跌了。

我觉得造成这些难题的一大原因是：**模型对环境缺少足够的信息。**

这导致了合成任务的时候，本质上是模型在靠自己的先验知识、靠对这个软件的了解程度在进行合成。所以合成的都是常见的按钮、常见的功能，比如 Word 里面的新建、另存为、调整行间距、字体等等。但是可能就很难合成宏编辑器、审阅—隐藏墨迹等相对冷门的功能。而这恰恰是模型缺的、需要提升的一大部分。对于相对更封闭的一些 PC 端软件来说，模型知道的就更少，合成的多样性和复杂程度就更差。

“20 个的时候还能靠语言模型的 long-tail knowledge 撑住；100 个的时候开始大量换皮、重新排列组合，behavioral diversity 很快坍缩。”

因为模型不够了解环境信息，所以它只能合成常见的任务，只敢合成简单的任务，任务多样性、复杂度上不去。

## WebFactory：让环境可观察

在 WebFactory 这个工作中，我们尝试合成网站，然后基于网站合成任务和验证器，然后用于 SFT 和 RL。我们发现如果 Web 是我们合成的，本质上我们拥有环境的所有信息，或者说环境对于模型来说是完全可观察的（也就是论文中的 observable），而这会：

1. 大大提升模型合成任务的难度、复杂度和多样性。
2. 因为幻觉导致的、合成出的不符合要求的任务基本消失。

模型有了环境信息了，比如网站有哪些按钮、某个餐厅的周日营业时间、商城的退换货政策等等，理论上模型可以穷尽这个环境的所有功能和信息，可以合成这个环境能提供的最复杂的任务。几乎不存在幻觉。

又因为模型有了环境信息，所以也可以一定程度上提升合成验证器的有效性。

所以，对于合成的环境而言（比如 Web、mobile），可以给模型更多环境信息作为补充给模型的 knowledge，来提升合成长难 agentic 任务的水平。

对于非合成的环境，可以给一个探索 agent，在合成任务之前先去探索环境，尽可能地获取环境信息作为 knowledge，从而搭建一个 knowledge-driven 的任务合成 pipeline。

## 难度悖论与环境知识的作用

“大家苦于造不出更难更复杂的任务”，从根本上来说，其实本身就是一个比较矛盾的点，我取名叫“难度悖论”：我们需要足够难的任务，本质上是想要任务难度达到甚至超过目前前沿模型的能力边界；我们又希望模型最好能正确合成对应的 verifier，而这个其实需要任务难度低于模型的能力边界。

提升模型对于环境信息的了解，从结果上来看，一定程度上提升了它在当前环境上的模型的能力上限，有助于合成更复杂、更多样的任务。在执行任务的时候，模型不知道这些信息，能力上限就低一些，就需要自己去探索环境，寻找更多信息和方法来解决这个任务。

当然，这也有自己的局限性，环境信息补全可以提升任务的可执行性和表面多样性，但不会自动带来高认知难度。进一步的高难度任务需要在规划深度、信息获取成本、约束复杂度、动态调整这些维度上做文章。这就需要设计一套完善精密的 pipeline 来做好了。

比如“在合成任务之前先去探索环境，尽可能地获取环境信息作为 knowledge”这里的 knowledge 可以不单单是环境信息，还可以是有助于模型合成任务时提升规划深度和复杂度的更高维度的信息。

从长远来说，我们做 Agent 数据构造，不能让 LLM “凭空想出更难的问题”，需要先把环境变成一个模型可以读取、搜索、组合、验证的世界模型，再在这个世界模型上持续寻找当前 policy 的能力边界。

那如果这个能做好，那未来模型有多强，就看咱们拥有多少个可探索、可组合、可验证，并且能够持续产生多样性 frontier tasks 的 environments。

## 顺便提一嘴最近很火的 RSI

随着模型能力不断提升，Agent post-training 的核心瓶颈会从“如何让模型完成任务”，转向“如何持续发现并构造模型尚未掌握、但又可执行、可验证、具有学习价值的新任务”。从这个角度看，造任务不再只是一个数据生产问题，而开始成为 RSI 中的关键基础设施。

可持续的自我改进闭环，需要当前 policy 能够理解和建模环境，识别自身尚未覆盖的 capability space，根据失败模式和能力边界生成新的任务，再借助程序化 verifier、环境内部状态或其他可执行反馈判断结果，并将这些信号重新用于下一轮训练。

模型因此不再只是在一个固定的数据分布上被动学习，而开始参与决定“下一阶段应该学习什么”。
