## Computer-use agent 的春天要来了吗

虽然目前各家大厂都在大力发展 coding agent，但是最前沿的模型的 coding 能力似乎快到瓶颈了。比如 Opus 4.8 就已经可以完成大多数代码任务，Opus 5 带来的提升在日常编程中已经不再明显。

Computer-use 会不会是下一步？Coding 场景毕竟太狭窄，下一步我们真正需要的是能跨多个软件、跨多个网站帮我们执行任务、完成工作的 agent。

**“在一个封闭工作空间里解决问题” → “在数字世界里闭环完成工作”。** Computer-use 是这个变化最重要的执行基础设施之一。

## 从复制粘贴到跨环境执行

比如：在邮件里收集今日待办，进入网站查看模型训练曲线和报错，进入另一个网站查看报错日志，连接 terminal 进行 debug，并查看办公软件上有无新的信息通知等等。目前 coding agent 做不到这些，但理想的 agent 应该能做到这些。

其实仔细想想模型进化的路线：从最开始的 chatbot，我们在一个对话框与模型对话，不停复制粘贴，承担模型输出内容的搬运工。然后到了 agent，模型接入 harness 之后，开始帮我们生成文件、编写代码，帮我们干活，coding agent 开始热门。

但 coding agent 还是不够，不能跨网站跨任务去执行，导致还是会有大家把网站内的报错粘贴给 coding agent，把日志下载下来喂给 coding agent，和最开始我们粘贴进聊天框没什么区别。

日常办公场景，大量步骤存在于：**browser + GUI + terminal + internal tools + communication software**。

Computer-use 的能力就是关键。

## 我期待的 AI 工作助手

因此，我坚定地看好 Computer-use agent。这是一个我期待了好几年的事情，我希望我们真的能做出来一个帮大家干活的 AI 工作助手，跨多个软件进行交互，在多个网站间搜集信息，然后完成一整个工作任务。

相比之下，Coding Agent 解决的是 **execution inside a workspace**。

Computer-use Agent 解决的是 **execution across environments**。Computer-use Agent 有机会让模型拥有与人类知识工作者近似完整的“数字行动空间”。
